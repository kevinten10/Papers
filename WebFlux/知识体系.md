## 🔍 核心概念解析

### 1. 响应式编程的本质

#### 问题域分析

**传统阻塞式模型的问题**：
```
请求 → 线程池分配线程 → 阻塞等待IO → 返回响应
         ↓
    线程资源有限
    高并发时线程耗尽
    上下文切换开销大
```

**响应式模型解决方案**：
```
请求 → 事件循环 → 非阻塞IO → 回调处理 → 返回响应
         ↓
    少量线程处理大量请求
    事件驱动，无阻塞等待
    资源利用率高
```

#### 核心思想

1. **数据流（Data Stream）**
   - 数据不是一次性返回，而是以流的形式持续推送
   - 类似于观察者模式的增强版

2. **异步非阻塞**
   - 不等待IO操作完成
   - 通过回调处理结果

3. **背压（Backpressure）**
   - 消费者控制数据流速
   - 防止生产者过快导致内存溢出

### 2. Reactive Streams 规范

#### 四个核心接口

```java
// 1. Publisher - 数据发布者
public interface Publisher<T> {
    void subscribe(Subscriber<? super T> s);
}

// 2. Subscriber - 数据订阅者
public interface Subscriber<T> {
    void onSubscribe(Subscription s);
    void onNext(T t);
    void onError(Throwable t);
    void onComplete();
}

// 3. Subscription - 订阅契约
public interface Subscription {
    void request(long n);  // 请求n个元素
    void cancel();         // 取消订阅
}

// 4. Processor - 既是发布者又是订阅者
public interface Processor<T, R> extends Subscriber<T>, Publisher<R> {
}
```

#### 交互流程

```
Publisher                    Subscription                    Subscriber
    │                            │                              │
    │─── subscribe(subscriber) ──>│                              │
    │                            │─── onSubscribe(sub) ────────>│
    │                            │<── request(n) ───────────────│
    │─── onNext(data) ───────────>│─── onNext(data) ───────────>│
    │                            │<── request(n) ───────────────│
    │─── onNext(data) ───────────>│─── onNext(data) ───────────>│
    │                            │                              │
    │─── onComplete() ───────────>│─── onComplete() ───────────>│
```

### 3. Project Reactor

#### Mono 和 Flux

**Mono**：0 或 1 个元素的异步序列
```java
Mono<String> mono = Mono.just("Hello");
Mono<String> empty = Mono.empty();
Mono<String> error = Mono.error(new RuntimeException());
```

**Flux**：0 到 N 个元素的异步序列
```java
Flux<Integer> flux = Flux.range(1, 10);
Flux<String> fromList = Flux.fromIterable(Arrays.asList("a", "b", "c"));
```

#### 操作符分类

1. **创建操作符**
   - `just()`, `empty()`, `error()`
   - `fromIterable()`, `fromArray()`
   - `range()`, `interval()`

2. **转换操作符**
   - `map()`: 同步转换
   - `flatMap()`: 异步转换，返回新的 Publisher
   - `concatMap()`: 保持顺序的 flatMap

3. **过滤操作符**
   - `filter()`: 条件过滤
   - `take()`: 取前N个
   - `skip()`: 跳过前N个
   - `distinct()`: 去重

4. **组合操作符**
   - `merge()`: 合并多个流
   - `zip()`: 组合多个流
   - `concat()`: 顺序连接

5. **错误处理**
   - `onErrorReturn()`: 错误时返回默认值
   - `onErrorResume()`: 错误时切换到备用流
   - `retry()`: 重试

### 4. Spring WebFlux 架构

#### 核心组件

1. **WebHandler**
   ```java
   public interface WebHandler {
       Mono<Void> handle(ServerWebExchange exchange);
   }
   ```

2. **RouterFunction**
   ```java
   RouterFunction<ServerResponse> route = RouterFunctions.route()
       .GET("/users", handler::getUsers)
       .POST("/users", handler::createUser)
       .build();
   ```

3. **HandlerFunction**
   ```java
   public interface HandlerFunction<T extends ServerResponse> {
       Mono<T> handle(ServerRequest request);
   }
   ```

#### 请求处理流程

```
HTTP Request
    ↓
WebHandler (DispatcherHandler)
    ↓
HandlerMapping (查找处理器)
    ↓
HandlerAdapter (适配处理器)
    ↓
HandlerFunction (业务逻辑)
    ↓
HandlerResultHandler (处理结果)
    ↓
HTTP Response
```

#### 线程模型

**Spring MVC (阻塞式)**：
- 每个请求一个线程
- 线程池大小：通常 200-500
- 线程阻塞等待IO

**Spring WebFlux (非阻塞式)**：
- 少量线程处理所有请求
- 默认线程数：CPU核心数
- 事件循环，无阻塞等待

## 🎨 设计模式应用

### 1. 观察者模式（Observer Pattern）

响应式编程本质上是观察者模式的扩展：
- Publisher = Subject（被观察者）
- Subscriber = Observer（观察者）
- Subscription = 订阅关系

### 2. 责任链模式（Chain of Responsibility）

WebFlux 的过滤器链：
```
Request → Filter1 → Filter2 → Filter3 → Handler → Response
```

### 3. 策略模式（Strategy Pattern）

不同的 HandlerAdapter 处理不同类型的处理器：
- RouterFunctionHandlerAdapter
- HandlerMethodAdapter
- WebSocketHandlerAdapter

### 4. 模板方法模式（Template Method）

WebHandler 定义了处理流程的骨架，具体步骤由子类实现。

## 🔄 数据流转

### 完整的数据流示例

```java
// 1. 数据源
Flux<String> source = Flux.just("apple", "banana", "cherry");

// 2. 转换
Flux<String> upper = source.map(String::toUpperCase);

// 3. 过滤
Flux<String> filtered = upper.filter(s -> s.length() > 5);

// 4. 组合
Flux<String> other = Flux.just("date", "elderberry");
Flux<String> merged = filtered.mergeWith(other);

// 5. 订阅
merged.subscribe(
    data -> System.out.println("Received: " + data),
    error -> System.err.println("Error: " + error),
    () -> System.out.println("Completed")
);
```

### 背压处理示例

```java
Flux.range(1, 1000)
    .onBackpressureBuffer(100)  // 缓冲100个元素
    .subscribe(
        data -> {
            // 慢速处理
            Thread.sleep(100);
            System.out.println(data);
        }
    );
```

## 🚀 性能优化要点

### 1. 线程池配置

```java
@Configuration
public class WebFluxConfig {
    @Bean
    public NettyReactiveWebServerFactory nettyReactiveWebServerFactory() {
        NettyReactiveWebServerFactory factory = new NettyReactiveWebServerFactory();
        factory.addServerCustomizers(httpServer -> 
            httpServer.tcpConfiguration(tcpServer -> 
                tcpServer.runOn(LoopResources.create("webflux", 4, true))
            )
        );
        return factory;
    }
}
```

### 2. 内存管理

- 使用 `onBackpressureBuffer()` 控制内存使用
- 避免在响应式流中缓存大量数据
- 及时释放不需要的资源

### 3. 错误处理

```java
Flux<String> flux = getData()
    .onErrorReturn("default")           // 返回默认值
    .onErrorResume(error -> {           // 切换到备用流
        if (error instanceof TimeoutException) {
            return getFallbackData();
        }
        return Flux.error(error);
    })
    .retry(3);                          // 重试3次
```

## 📊 适用场景分析

### 适合 WebFlux 的场景

1. **高并发API服务**
   - 大量并发连接
   - 需要处理大量请求

2. **实时数据流**
   - WebSocket 连接
   - Server-Sent Events (SSE)
   - 流式数据处理

3. **微服务网关**
   - API Gateway
   - 请求路由和转发
   - 负载均衡

4. **IoT 应用**
   - 大量设备连接
   - 实时数据采集

### 不适合 WebFlux 的场景

1. **简单 CRUD 应用**
   - 传统 MVC 更简单
   - 开发效率更高

2. **阻塞式数据库访问**
   - JDBC 是阻塞的
   - 需要使用 R2DBC

3. **团队技术栈不匹配**
   - 学习成本高
   - 调试困难
