## 四、避坑指南

### 4.1 IDE 选型避坑

| 坑点 | 解决方案 |
|-----|---------|
| 一次让 AI 改太多文件 | 拆成 3-7 个子任务，每步验证 |
| 不限制改动范围 | 明确"允许改"和"禁止改"的目录 |
| 忽视代码审查 | 强制 diff 审查，不要直接接受 |
| 过度依赖单一工具 | 关键任务用第二模型交叉验证 |
| 不关注成本变化 | 定期检查订阅和用量 |

### 4.2 CLI 使用避坑

| 坑点 | 解决方案 |
|-----|---------|
| 自动执行危险命令 | 关闭 YOLO 模式，人工确认 |
| 大范围自动重构 | 先给范围限制，分步执行 |
| 忽视 Git 状态 | 每次改动前确保干净工作区 |
| 不保存检查点 | 重要节点手动创建检查点 |

### 4.3 模型使用避坑

| 坑点 | 解决方案 |
|-----|---------|
| 盲目相信模型输出 | 关键结论要来源核验 |
| 上传敏感信息 | 先脱敏再使用云模型 |
| 忽视上下文限制 | 长文档先分段处理 |
| 单一模型依赖 | 重要决策用多模型交叉验证 |

## 五、进阶技巧

### 5.1 混合策略

**日常开发流：**
1. Gemini CLI（免费）做日常调研和草稿
2. Cursor（$20）做代码实现
3. Claude Code（按需）做关键重构

**方案设计流：**
1. DeepSeek（免费）做初步调研
2. Claude（$20）做方案设计
3. NotebookLM（免费）生成汇报材料

### 5.2 成本控制

**免费层最大化：**
- Gemini CLI：1000 请求/天
- Qwen CLI：2000 请求/天
- DeepSeek：极低 API 成本
- Zed / Aider / Cline：完全免费

**付费层精准投放：**
- Cursor：日常主力
- Claude Code：关键任务 only
- o1/o3：复杂推理 only

### 5.3 效率提升

**Prompt 模板化：**
```
# 需求澄清模板
你是[角色]，我要做[目标]。
背景是[现状]，约束是[时间/范围/技术栈]。
请输出：
1) 需要确认的 8 个问题
2) 验收标准（DoD）
3) 风险点与规避策略

# 代码改动模板
只允许修改：[目录/文件]
禁止修改：[目录/文件]
先输出：改动清单 + 影响面 + 回归点
每步输出 diff 等你确认
```
