# 算法推荐

## 流程

### 1. 训练模型 (离线训练)

1. **数据准备 (Data Engineering)**：
   - 从日志系统 (Kafka/Flink) 或数据库 (Hive/Hadoop) 收集用户行为数据。
   - 数据清洗：去噪、去重、异常值处理。
   - 样本构造：定义正负样本 (例如：点击为正，曝光未点击为负)。

2. **特征工程 (Feature Engineering)**：
   - **用户特征**：人口统计学信息、长期偏好、短期兴趣。
   - **物品特征**：类别、标签、内容属性、统计热度。
   - **上下文特征**：时间、地点、设备类型。
   - **交叉特征**：用户与物品的交互特征 (如：用户对该类别的历史点击率)。

3. **模型选择与训练**：
   - 选择模型：深度学习模型 (DeepFM, DIN, BST) 或 传统模型 (XGBoost, LightGBM)。
   - 环境：使用 Docker 容器，配置 GPU (CUDA) 和 大内存。
   - 训练：编写 Python 脚本 (PyTorch/TensorFlow)，进行超参数搜索。

4. **模型导出与评估**：
   - **离线评估**：计算 AUC, LogLoss, Recall@N 等指标。
   - **格式转换**：将模型导出为通用格式，如 `ONNX` 或 `TensorRT`。

### 2. 部署模型 (在线服务)

1. **模型加载**：
   - 后端服务 (C++, Java 或 Python/FastAPI) 加载 `ONNX` 文件。
   - 使用推理引擎优化：如 `ONNX Runtime`, `TensorRT`, `Triton Inference Server`。

2. **高性能服务**：
   - 内存预热：防止首次请求耗时过长。
   - 并行计算：利用多核 CPU 或 GPU 加速推理。
   - 缓存机制：对高频请求结果进行缓存。

3. **接口定义**：
   - 定义标准的推理 API (gRPC 或 RESTful)，接收特征，返回分数或 ID 列表。

### 3. 调用模型

1. 调用后端服务，提供输入数据

2. 后端接收输入数据，调用模型进行推理

3. 模型推理完成，将结果返回给后端

4. 后端基于模型推理结果，进行后续逻辑处理

### 4. 个性化推荐全链路逻辑 (核心)

推荐系统通常采用“漏斗式”架构，逐层过滤数据：

1. **召回 (Recall)**：
   - **目标**：从海量数据 (千万级) 中快速选出几百个候选项。
   - **手段**：
     - 基于协同过滤 (Collaborative Filtering)。
     - 基于向量检索 (Vector Search / HNSW)：将用户和物品映射到同一空间。
     - 热门召回、新品召回。

2. **粗排 (Pre-Ranking)**：
   - **目标**：从几百个候选项中选出几十个。
   - **手段**：使用轻量级模型 (如双塔模型)，只使用部分特征，计算耗时极低。

3. **精排 (Ranking)**：
   - **目标**：对几十个候选项进行精准打分，决定展示顺序。
   - **手段**：使用深度复杂模型 (如 Wide&Deep, DeepFM)，使用全量特征 (包括强特征、实时交互特征)。

4. **重排 (Re-Ranking / Strategy)**：
   - **目标**：根据业务规则调整最终列表。
   - **手段**：
     - 打散逻辑 (防止连续出现同类内容)。
     - 强插/置顶 (运营需求)。
     - 多目标优化 (同时平衡点击率、转化率、停留时间)。

### 5. 模型实时更新 (Online Learning)

1. **实时特征流**：
   - 使用 Flink 处理实时用户行为，秒级更新特征仓库 (Feature Store)。
2. **在线学习**：
   - 模型不只在离线训练，还可以基于实时反馈进行小步快跑的更新。
3. **近线处理**：
   - 捕捉用户“刚刚看过”的兴趣，实时调整召回结果。

### 6. 传统模型转为 LLM (新趋势)

1. **Embedding 增强**：
   - 使用 LLM 提取物品的语义向量 (Text Embedding)，提升召回精度。
2. **生成式推荐**：
   - 直接利用 LLM (如 GPT-4, Llama) 的推理能力，通过 Prompt 提供用户历史，生成推荐理由或推荐列表。
3. **重排阶段介入**：
   - 在最后精选阶段，利用 LLM 对 Top 5 结果进行深度理解和排序。

### 7. 算法工程基础设施 (Infrastructure)

1. **A/B Testing**：
   - 算法上线前必须经过分流测试，对比 CTR、人均停留等指标，数据证明有效后再全量。
2. **特征仓库 (Feature Store)**：
   - 保证离线训练和在线推理使用同一套特征定义，防止“特征穿越”。
3. **监控与告警**：
   - 监控模型性能衰减、特征缺失率、推理耗时 (P99) 等关键指标。
4. **模型版本管理**：
   - 支持一键回滚、多版本灰度。
