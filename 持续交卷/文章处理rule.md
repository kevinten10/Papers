# 📝 持续交卷文章处理规则

## 🎯 概述

本文档定义了将 `持续交卷` 项目中各模块的随笔记录转换为符合微信公众号格式的标准化处理规则。

**适用范围**：B 级内容（日常学习笔记、碎片知识整理）。A 级深度文章请使用 `社媒分发rule.md` 进行多平台分发处理。分级标准见 `社媒分发rule.md` 第一步。

**处理目标**：将各模块的项目符号笔记转换为结构完整、逻辑清晰的公众号文章，在保持原始含义不变的前提下，提升可读性和专业性。

**输出规范**：
- **推荐模式**：日期聚合模式，将同日期所有内容合并为单篇文章
- **输出位置**：`持续交卷/公众号文章/YYYYMM/YYYY-MM-DD-公众号.md`
- **可选模式**：独立文档模式，每个文件单独生成公众号版文档

## 🏗️ 模块识别系统

### 持续交卷模块体系

系统支持持续交卷项目的6个核心模块，每个模块都有独特的处理需求：

#### 1. 阅读笔记模块 (reading-notes)
**路径特征**：`持续交卷/阅读笔记/`
**内容特征**：理论性强，包含批判性思考、知识关联、实际应用
**典型结构**：资料信息、核心观点、个人思考、知识关联、实际应用
**处理重点**：保持学术性，突出知识体系构建

#### 2. 英语资讯模块 (english-news)
**路径特征**：`持续交卷/英语资讯/`
**内容特征**：英语写作，6段式固定结构，语言学习导向
**典型结构**：文章信息、核心要点、个人见解、新学词汇、语法学习、应用思考
**处理重点**：保留英语原文结构，添加适当的中文说明

#### 3. 算法模块 (algorithm)
**路径特征**：`持续交卷/算法/`
**内容特征**：代码密集，包含解题思路、复杂度分析、测试用例
**典型结构**：题目描述、解题思路、代码实现、复杂度分析、优化思路
**处理重点**：正确处理代码块，保持算法逻辑的清晰性

#### 4. 技术写作模块 (tech-writing)
**路径特征**：`持续交卷/技术写作/`
**内容特征**：实践导向，包含代码示例、工具推荐、最佳实践
**典型结构**：引言、核心内容、最佳实践、工具资源、总结展望
**处理重点**：保留代码示例和技术细节，突出实用价值

#### 5. AI原理模块 (ai-principles)
**路径特征**：`持续交卷/AI原理/`
**内容特征**：技术深度高，概念密集，包含大量专业术语
**典型结构**：技术概念讲解，原理剖析，应用场景
**处理重点**：准确传达技术概念，适当添加解释

#### 6. 其他模块 (other)
**路径特征**：其他未分类模块
**内容特征**：根据实际情况动态识别
**处理策略**：回退到通用内容类型识别

### 模块识别算法

**识别规则**：
1. **优先路径识别**：根据文件路径直接识别模块类型
2. **内容特征识别**：当路径识别失败时，通过内容特征进行识别
3. **智能回退**：默认回退到通用处理策略

**路径识别映射**：
- `持续交卷/阅读笔记/` → 阅读笔记模块
- `持续交卷/英语资讯/` → 英语资讯模块
- `持续交卷/算法/` → 算法模块
- `持续交卷/技术写作/` → 技术写作模块
- `持续交卷/AI原理/` → AI原理模块

**内容特征识别规则**：
- **英语资讯**：包含"文章信息"、"核心要点"、"个人见解"等6段式结构
- **算法**：包含代码块、复杂度分析、解题思路等特征
- **技术写作**：包含最佳实践、工具推荐、代码示例
- **AI原理**：包含大量AI相关术语和技术概念
- **阅读笔记**：包含资料引用、知识关联、批判性思考

## 🔄 转换原则

### 核心准则

1. **内容保真**：不改变原始信息的准确性和核心含义
2. **结构优化**：从碎片化笔记转换为连贯文章
3. **读者导向**：考虑公众号读者的阅读习惯和理解水平
4. **适度扩充**：在保持简洁的同时，适当添加上下文和解释
5. **内容精简**：精简冗余信息，提升信息密度，提高阅读效率

### 质量底线

- ✅ 保持所有原始数据和事实准确
- ✅ 保留所有引用来源和出处
- ✅ 不添加主观评价或推测内容
- ❌ 不改变专业术语的准确含义
- ❌ 不夸大或缩小数据范围

### 内容精简规范

#### 精简原则
- **核心内容保护**：确保所有关键概念、技术要点和核心洞察完整保留
- **冗余信息清理**：删除重复解释、过长的示例和非必要细节
- **表达优化**：合并相似概念，使用更精炼的表达方式
- **信息密度提升**：提高单位内容的信息承载量

#### 精简策略
1. **词汇列表优化**：将详细的词汇解释列表精简为表格形式或核心词汇汇总
2. **语法示例压缩**：保留关键句型，去除过多相似示例
3. **概念合并**：将相关但分离的概念进行逻辑合并
4. **总结提炼**：将长段阐述提炼为要点总结

#### 精简效果评估
- **内容完整性**：核心信息无遗漏，逻辑关系保持清晰
- **阅读效率**：信息密度提升30%以上，阅读时间缩短
- **表达质量**：语言更精炼，重点更突出
- **用户体验**：避免信息过载，提升阅读满意度

## 🎨 智能主题选择策略

### 基于模块的主题推荐算法

系统基于模块类型进行智能主题推荐：

**模块专用主题映射**：
- **阅读笔记**：`maize`（学习主题，柔和舒适）
- **英语资讯**：`rainbow`（彩色主题，增加活力）
- **算法**：`lapis`（技术主题，清爽专业）
- **技术写作**：`pie`（现代主题，时尚专业）
- **AI原理**：`lapis`（技术主题，严肃专业）

### 动态主题选择规则

#### 基于内容长度的选择
- **短文（<1000字）**：推荐 `rainbow` 或 `pie`，增强视觉吸引力
- **中篇（1000-3000字）**：推荐 `default` 或 `lapis`，平衡可读性
- **长文（>3000字）**：推荐 `maize` 或 `phycat`，减少视觉疲劳

#### 基于模块特点的调整
- **代码密集内容**：强制使用 `lapis` 技术主题
- **学术内容**：使用 `lapis` 正式主题
- **创意内容**：使用 `rainbow` 彩色主题
- **长文档**：避免太花哨的主题

### 步骤2：主体内容结构化

#### 通用转换策略

**从项目符号 → 段落叙述**：

**原始格式**：
```
## 1. RCS富媒体将成为传统短信的替代方案

  • RCS (RBM) 成为营销短信核心替代方案：2026年RCS已实现全面普及，支持品牌认证与富媒体卡片交互。相比传统短信，其点击率（CTR）平均提升3-5倍，且支持实时已读回执，有效解决B2C场景的信任与转化痛点。[Wikipedia-RCS] [GSMA技术规格]
```

**转换后格式**：
```markdown
### RCS富媒体通信：传统短信的革新替代

RCS（Rich Communication Services，富媒体通信服务）正在成为营销短信的核心替代方案。随着2026年的全面普及，RCS提供了品牌认证和富媒体卡片交互功能。

**核心优势**：
- 点击率显著提升：相比传统短信，CTR平均提升3-5倍
- 实时已读回执：有效解决B2C场景的信任与转化痛点
- 富媒体支持：支持图片、视频等多媒体内容

*数据来源：[Wikipedia-RCS] [GSMA技术规格]*
```

#### 内容扩充原则

1. **结构化分解**：将长段落分解为要点，便于阅读
2. **概念解释**：对专业术语进行简要解释，但不改变原意
3. **逻辑连接**：添加过渡词使内容连贯
4. **数据可视化**：用列表或表格形式呈现数据

### 步骤3：图片和媒体插入

**强制要求**：微信公众号要求文章必须包含至少一张图片

**插入策略**：
- 在相关段落插入主题相关的Unsplash图片
- 使用标准尺寸：`w=800&h=400&fit=crop&crop=center`
- 图片alt文本：描述性文字，便于SEO

**图片链接验证规范**：
- **有效性检查**：强制验证所有图片链接的有效性
- **验证方法**：使用浏览器检查HTTP响应状态，确保返回200状态码
- **失效处理**：发现无效链接时，立即替换为经过验证的有效链接
- **质量要求**：确保图片清晰度足够，主题相关性强，格式标准

**输出位置**：与原始文件同一目录
**命名格式**：`[原始文件名]-公众号版.md`
**目录保持**：严格保持原始目录层次结构

### 批处理策略

#### 多文件处理
- **支持范围**：一次可处理多个文件
- **分组策略**：同日期同模块文件可选择性整合
- **处理顺序**：按文件路径字典序处理

#### 同日期内容整合
- **双模式支持**：支持独立文档模式和日期聚合模式
- **默认模式**：日期聚合模式，将同日期所有内容合并为单篇文章
- **可选模式**：独立文档模式，每个原始文件生成单独公众号版文档

##### 日期聚合模式（推荐）
- **触发条件**：同日期的所有原始文件
- **整合策略**：按模块顺序合并为综合文章
- **合并顺序**：阅读笔记 → 英语资讯 → 算法 → AI原理
- **文件命名**：`持续交卷/公众号文章/YYYYMM/YYYY-MM-DD-公众号.md`
- **内容分隔**：各模块间使用分割线和二级标题分隔

##### 独立文档模式
- **触发条件**：需要单独发布或内容高度独立的情况
- **文件命名**：`[原始文件名]-公众号版.md`，保持原始文件名结构
- **存储位置**：与原始文件同一目录

#### 状态报告
- 处理开始：显示待处理文件列表
- 处理进度：实时显示当前文件状态
- 处理完成：汇总成功/失败统计

### 版本控制机制

#### 文件存在处理
- **检测机制**：检查目标路径是否已存在公众号版文件
- **处理选项**：
  - `覆盖`：直接覆盖现有文件（默认）
  - `跳过`：跳过已存在文件
  - `备份`：备份原文件后覆盖

#### 时间戳记录
```yaml
---
title: [标题]
cover: [封面图]
processed_at: 2026-01-09T10:30:00Z
source_file: [原始文件路径]
---
```

#### 增量更新支持
- 检测原始文件修改时间
- 仅在原始文件更新时重新处理
- 保留手动调整的内容

### 错误处理机制

#### 文件级错误
- **文件不存在**：记录错误并继续处理其他文件
- **读取权限**：提示权限问题并跳过
- **编码问题**：尝试UTF-8解码，失败则跳过

#### 内容级错误
- **格式异常**：记录错误位置，继续处理其他部分
- **模块识别失败**：回退到通用处理策略
- **图片获取失败**：使用默认图片替代

#### 输出级错误
- **写入权限**：提示目录权限问题
- **磁盘空间**：检查可用空间，不足则暂停
- **网络错误**：图片下载失败时使用本地缓存
