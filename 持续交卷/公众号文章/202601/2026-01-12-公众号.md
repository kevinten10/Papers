## 🔧 算法模块

### Redis技术架构深度解析

#### 数据结构设计精要

Redis采用多种数据结构实现高性能键值存储，每种数据结构都针对特定应用场景进行了优化：

**String类型**：基于简单动态字符串（SDS）实现，提供高效的字符串操作和自动内存管理。

**Hash类型**：采用哈希表或压缩列表两种底层实现，根据数据量自动选择最优存储结构。

**List类型**：基于快速列表（QuickList）实现，将双向链表与压缩列表结合，既保证操作性能又控制内存占用。

**Set类型**：使用哈希表或整数集合实现，支持高效的集合运算操作。

**Zset类型**：结合跳表和哈希表实现，为排行榜和带权重的队列场景提供完美支持。

#### 持久化机制对比

Redis提供了RDB和AOF两种持久化机制，各有特色：

**RDB快照持久化**：
- 记录某一时刻的完整数据状态
- 文件体积小，恢复速度快
- 通过save或bgsave命令触发
- 可能丢失最近的修改数据

**AOF追加文件持久化**：
- 记录所有写操作命令日志
- 提供三种刷盘策略：always（最安全但性能最低）、everysec（平衡选择）、no（性能最好但最不安全）
- 数据丢失风险小，但文件体积较大

**混合持久化**：结合RDB和AOF优点，在性能和数据安全性之间取得最佳平衡。

#### 高性能架构设计

Redis高性能源于其精妙架构设计：

**纯内存操作**：所有数据存储在内存中，读写速度极快。

**单线程模型**：避免多线程上下文切换开销，通过高效I/O多路复用处理并发请求。

**事件驱动机制**：基于epoll等高效I/O多路复用技术，实现单线程处理高并发。

#### 常见问题与解决方案

**缓存穿透防护**：
- **布隆过滤器拦截**：提前判断请求数据是否存在，避免无效查询
- **空值缓存策略**：对不存在数据设置短期空值缓存

**缓存击穿防护**：
- **热点数据永不过期**：避免失效瞬间的集中访问
- **互斥锁机制**：控制同一时刻只有一个线程访问数据库

**缓存雪崩防护**：
- **过期时间随机化**：分散缓存失效时刻
- **多级缓存架构**：结合本地缓存和分布式缓存

**数据一致性保障**：
- **双删策略**：删除缓存后更新数据库，再次删除缓存确保一致性
- **同步更新机制**：数据库更新时同步更新缓存

#### 核心技术问题解答

**Redis单线程高并发原理**：
Redis采用单线程处理所有命令请求，通过高效I/O多路复用机制（epoll）避免线程切换开销。内存操作和原子性命令设计确保了高性能并发处理能力。

**持久化机制选择策略**：
- RDB适合备份和快速恢复场景
- AOF提供更好的数据安全性
- 生产环境推荐RDB+AOF混合持久化

**分布式锁实现方案**：
基于Redis的SET NX EX命令实现，结合Lua脚本确保原子性操作。对于高可用需求，可采用Redisson或Redlock多节点方案。

**过期键清理机制**：
结合定期删除、惰性删除和内存不足时的主动淘汰三重策略，确保过期数据及时清理又不影响性能。

#### 一致性算法解析

**主流算法概览**：
Paxos和Raft是分布式系统一致性的两大主流算法，各有特色的应用场景。

**Paxos算法**：
- 基于两阶段提交思想
- 三个核心角色：Proposer（提案者）、Acceptor（接受者）、Learner（学习者）
- 通过提案编号和投票机制确保一致性

**Raft算法**：
- 简化版一致性算法，通过领导者选举、日志复制、安全性保证实现
- 任期机制确保单领导者，避免脑裂问题
- 广泛应用于etcd、Consul等分布式系统中

**一致性模型分类**：
- **强一致性**：所有节点同时看到最新数据
- **弱一致性**：数据更新后不保证立即可见
- **最终一致性**：经过一段时间后数据达到一致状态

#### JVM内存模型详解

**内存区域划分**：
JVM内存分为线程私有和线程共享两大部分：

- **线程私有**：栈（Stack）和程序计数器（Program Counter）
- **线程共享**：堆（Heap）和方法区（Method Area）

**方法区演进**：
JDK8之前使用永久代存储方法区内容，JDK8及之后使用元空间（本地内存）替代，避免了永久代内存限制问题。

**垃圾回收策略**：

**回收类型**：
- Minor GC：新生代垃圾回收
- Major GC：老年代垃圾回收  
- Full GC：整个堆和方法区的全面回收

**经典算法**：
- **标记-清除**：简单高效但产生内存碎片
- **复制算法**：无碎片但内存利用率低，适合新生代
- **标记-整理**：移动对象消除碎片，增加整理开销
- **分代算法**：新生代用复制算法，老年代用标记-清除/整理

**现代化GC技术**：
- **G1**：分代+区域化+标记整理，兼顾吞吐量和停顿时间
- **ZGC**：标记-整理算法，低延迟，适合超大堆场景

### 算法实现：句子单词反转

```java
class Solution {

    /**
     * 反转句子中的英语单词
     * 
     * @param s 输入字符串
     * @return 单词反转后的字符串
     */
    String reverseWords(String s) {
        StringBuilder builder = new StringBuilder();

        int tail = s.length() - 1;

        while (tail >= 0) {
            // 跳过空格
            while (tail >= 0 && s.charAt(tail) == ' ') {
                tail--;
            }

            if (tail < 0) {
                break;
            }

            int end = tail;
            while (tail >= 0 && s.charAt(tail) != ' ') {
                tail--;
            }

            if (builder.length() > 0) {
                builder.append(" ");
            }

            builder.append(s.substring(tail + 1, end + 1));
        }

        return builder.toString();
    }
}
```

该算法通过双指针技术，从字符串末尾开始遍历，依次提取每个单词并反转顺序。时间复杂度为O(n)，空间复杂度为O(n)，是一种高效的原地反转解决方案。
