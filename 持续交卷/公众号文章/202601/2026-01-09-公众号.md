## 🔧 算法模块

### I/O模型与多路复用

#### I/O操作的两个阶段

**数据准备阶段（Data Preparation）**
- 数据从网络到达网卡，网卡通过DMA（Direct Memory Access）技术将数据直接复制到内核缓冲区
- 这个阶段不涉及CPU参与，完全由硬件完成
- 属于"等待数据就绪"的过程

**数据复制阶段（Data Copy）**
- 数据从内核缓冲区复制到用户缓冲区，进入用户态空间
- 对于JVM：由于JVM堆内存地址会因GC动态变化，无法直接与内核交互
- 需要先复制到堆外内存（Direct Memory），再复制到JVM堆内内存
- 零拷贝技术主要优化这个阶段，减少不必要的CPU拷贝操作

**零拷贝技术的核心优化**
零拷贝（Zero-copy）技术的本质是尽量避免多余的数据复制操作，减少内核空间和用户空间之间的拷贝次数。在传统I/O模型中，数据通常需要经历多次复制。

#### 传统I/O的数据复制流程
1. 磁盘 → 内核缓冲区（DMA拷贝）
2. 内核缓冲区 → 用户缓冲区（CPU拷贝）
3. 用户缓冲区 → Socket缓冲区（CPU拷贝）
4. Socket缓冲区 → 网卡（DMA拷贝）

共4次拷贝，其中2次CPU拷贝，2次DMA拷贝，还涉及4次上下文切换。

#### 零拷贝技术的优化方案

**mmap + write**
- 使用内存映射（mmap）将内核缓冲区映射到用户空间
- 减少一次CPU拷贝：磁盘 → 内核缓冲区 → Socket缓冲区 → 网卡
- 共3次拷贝（1次CPU拷贝，2次DMA拷贝）

**sendfile**
- Linux 2.1引入，直接在内核空间完成数据传输
- 磁盘 → 内核缓冲区 → Socket缓冲区 → 网卡
- 共3次拷贝（1次CPU拷贝，2次DMA拷贝），但减少了上下文切换

**sendfile + DMA gather copy**
- Linux 2.4优化，支持scatter-gather DMA
- 只需将文件描述符和偏移量传递给Socket缓冲区
- 磁盘 → 内核缓冲区 → 网卡（直接DMA）
- 共2次拷贝（都是DMA拷贝），真正的零拷贝

#### JVM中的零拷贝

Java NIO的FileChannel.transferTo()方法底层使用sendfile系统调用。DirectByteBuffer使用堆外内存，避免JVM堆内存的额外拷贝。堆外内存地址固定，不受GC影响，可以直接与内核交互。

#### 堆外内存（Direct Memory）详解

**概念与特点**
- **定义**：位于JVM进程地址空间但不在JVM堆内存中的内存区域
- **分配方式**：通过JNI（Java Native Interface）直接调用malloc()分配
- **生命周期**：不受JVM GC管理，由开发者手动管理
- **地址稳定性**：内存地址固定，不会因为GC而移动

**JVM堆内 vs 堆外内存对比**

| 特性 | 堆内内存 | 堆外内存 |
|------|----------|----------|
| 管理方式 | GC自动管理 | 手动管理 |
| 地址稳定性 | GC时可能移动 | 地址固定 |
| 性能开销 | JNI调用开销 | 直接与内核交互 |
| 内存效率 | 可能触发Full GC | 避免GC压力 |

#### 零拷贝在Java中的实现

**FileChannel.transferTo() 示例**

```java
public void zeroCopyTransfer(File source, File target) throws IOException {
    try (FileChannel sourceChannel = FileChannel.open(source.toPath());
         FileChannel targetChannel = FileChannel.open(target.toPath(),
             StandardOpenOption.CREATE, StandardOpenOption.WRITE)) {

        long position = 0;
        long size = sourceChannel.size();

        // 使用sendfile实现零拷贝
        while (position < size) {
            long transferred = sourceChannel.transferTo(position, size - position, targetChannel);
            position += transferred;
        }
    }
}
```

**DirectByteBuffer网络传输**

```java
public void directBufferNetwork(SocketChannel channel) throws IOException {
    // 分配堆外内存
    ByteBuffer buffer = ByteBuffer.allocateDirect(64 * 1024);

    try {
        while (channel.read(buffer) > 0) {
            buffer.flip();
            // 直接使用堆外内存与内核交互，无需额外拷贝
            channel.writeAndFlush(buffer);
            buffer.clear();
        }
    } finally {
        // 重要：清理堆外内存
        ((DirectBuffer) buffer).cleaner().clean();
    }
}
```

### I/O多路复用进阶

#### epoll vs select/poll 的效率对比

**监听FD数量限制**
- select使用固定大小的fd_set（通常1024），超过限制需要修改内核宏
- poll理论上无上限，但仍然需要遍历所有fd，时间复杂度O(n)
- epoll监听FD数量理论上无上限，使用红黑树管理，时间复杂度O(1)

**数据结构差异**
- select/poll：每次调用都需要拷贝fd_set/pollfd数组
- epoll：只在添加FD时拷贝一次，epoll_wait只返回就绪FD

**性能对比总结**

| 特性 | select | poll | epoll |
|------|--------|------|-------|
| FD限制 | ~1024 | 无理论上限 | 理论无上限 |
| 时间复杂度 | O(n) | O(n) | O(1) |
| 拷贝次数 | 每次都拷贝 | 每次都拷贝 | 只拷贝就绪FD |
| 适用场景 | 小规模连接 | 中等规模 | 大规模高并发 |

#### 同步I/O vs 异步I/O

**同步I/O**：I/O操作完成后才返回，线程在等待期间被阻塞
**异步I/O**：发起I/O请求后立即返回，通过回调或信号通知完成

#### epoll的LT和ET模式

**LT模式（Level Triggered）**：
- 只要FD上有未处理的事件，就会不断触发
- 编程简单，但可能产生重复触发

**ET模式（Edge Triggered）**：
- 只在FD状态发生变化时触发一次
- 高效性能，但编程复杂，必须一次性处理完所有数据

#### Reactor模式：基于I/O复用的事件驱动架构

**核心组件**：
- Reactor：负责监听I/O事件，将就绪事件分发给相应Handler
- Handler：处理具体I/O事件（Acceptor、Reader、Writer）
- Demultiplexer：实际的I/O多路复用实现

### 交替打印算法实现

基于信号量的多线程同步机制，实现两个线程交替打印"foo"和"bar"。

```java
import java.util.concurrent.Semaphore;

class FooBar {
    int n;
    Semaphore fooSem = new Semaphore(1);
    Semaphore barSem = new Semaphore(0);

    FooBar(int n) {
        this.n = n;
    }

    void foo() {
        for (int i = 0; i < n; i++) {
            try {
                fooSem.acquire();
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
            System.out.println("foo");
            barSem.release();
        }
    }

    void bar() {
        for (int i = 0; i < n; i++) {
            try {
                barSem.acquire();
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
            System.out.println("bar");
            fooSem.release();
        }
    }

    public static void main(String[] args) throws InterruptedException {
        FooBar fooBar = new FooBar(5);

        Thread fooThread = new Thread(() -> fooBar.foo());
        fooThread.start();

        Thread barThread = new Thread(() -> fooBar.bar());
        barThread.start();

        Thread.sleep(5000);
    }
}
```

**算法原理**：
- 使用两个信号量实现线程同步
- fooSem初始值为1，允许foo线程先执行
- barSem初始值为0，阻塞bar线程
- 每次打印后释放对方线程的信号量
