## 🔧 算法模块

### Java并发编程核心知识体系

Java并发编程是后端开发的核心技能之一，涉及多线程、同步机制、原子操作等关键概念。掌握这些知识有助于构建高性能、高并发的应用程序。

#### 线程不安全的根本原因

多线程环境下线程不安全问题的核心源于Java内存模型（JMM）的三大特性没有得到有效保证。

##### 可见性问题
现代计算机采用多级缓存架构，当多个线程运行在不同CPU核心时，每个线程可能在自己的工作内存（CPU缓存）中维护变量副本。一个线程修改共享变量后，其他线程可能无法立即看到最新值。

##### 原子性问题
看似简单的操作（如i++）实际包含读取、计算、写入三个步骤，在多线程环境下这些步骤可能被其他线程中断，导致操作不完整。

##### 有序性问题
编译器和CPU为了优化性能，会对指令进行重排序。虽然重排序在单线程环境下不会影响结果，但在多线程环境下可能导致意外的执行顺序。

#### volatile关键字的底层机制

volatile是Java提供的轻量级同步机制，保证变量的可见性和有序性，但不保证原子性。

##### 核心特性
- **可见性**：volatile变量的修改对所有线程立即可见，通过内存屏障保证
- **有序性**：volatile通过内存屏障禁止指令重排序
- **无原子性**：复合操作如i++仍然不是线程安全的

##### 底层实现
1. **内存屏障**：JVM在volatile变量读写时插入屏障指令
2. **缓存一致性**：遵循MESI协议确保缓存同步
3. **汇编层面**：生成lock前缀的特殊指令

#### synchronized关键字原理

synchronized是Java内置的悲观锁机制，通过对象监视器monitor保证临界区代码的原子性、可见性、有序性。

##### 字节码层面
基于monitorenter和monitorexit指令，获取和释放对象锁。

##### JVM层面
每个对象关联一个监视器，线程通过竞争监视器所有权实现同步。

##### 锁优化机制
JDK 1.6之后引入分级锁机制：
- **偏向锁**：同一个线程多次进入同步块，减少CAS操作
- **轻量级锁**：多个线程竞争时，通过自旋避免线程阻塞
- **重量级锁**：竞争激烈时升级为操作系统互斥量

#### 线程生命周期状态

Java线程拥有六种状态：
1. **NEW**：已创建但未调用start()
2. **RUNNABLE**：就绪和运行状态
3. **BLOCKED**：等待synchronized锁
4. **WAITING**：无限期等待
5. **TIMED_WAITING**：限期等待
6. **TERMINATED**：中断或执行完毕

#### CAS原理与ABA问题

##### CAS核心机制
CAS（Compare-And-Swap）是一种乐观锁实现，通过硬件指令保证原子性操作。包含三个参数：内存位置V、预期原值A、新值B。

##### ABA问题及解决方案
**问题描述**：线程1读取值A，线程2将A改为B又改回A，此时线程1的CAS操作会成功，但实际上值已被修改。

**解决方案**：
1. **AtomicStampedReference**：使用版本号解决ABA问题
2. **AtomicMarkableReference**：只关心是否被修改过

#### ThreadLocal内存泄漏问题

ThreadLocal为每个线程提供独立变量副本，避免共享变量竞争。

##### 内存泄漏成因
使用弱引用存储ThreadLocal对象key，当对象被回收时key变为null，但value仍然存在。

##### 解决方案
使用完毕后主动调用remove()方法清理资源。

#### 线程池核心参数与执行流程

##### 核心参数
- corePoolSize：核心线程数
- maximumPoolSize：最大线程数
- keepAliveTime：空闲线程存活时间
- workQueue：工作队列
- threadFactory：线程工厂
- handler：拒绝策略

##### 执行流程
1. 线程数 < corePoolSize → 创建新线程
2. 线程数 ≥ corePoolSize → 放入队列
3. 队列满 && 线程数 < maximumPoolSize → 创建新线程
4. 队列满 && 线程数 ≥ maximumPoolSize → 执行拒绝策略

#### ConcurrentHashMap实现原理

##### JDK 1.7：分段锁
采用16个Segment，默认每个Segment维护一个HashTable。

##### JDK 1.8：CAS + synchronized
摒弃分段锁，采用CAS和synchronized结合，减少内存开销。

**核心特性**：
- 线程安全：CAS和synchronized保证并发安全
- 高效并发：读操作完全无锁，写操作只锁住修改节点
- 扩容机制：采用分段迁移，避免全局迁移

#### 死锁产生的四个必要条件

1. **互斥条件**：资源只能被一个线程占用
2. **请求与保持条件**：线程持有资源的同时请求其他资源
3. **不可剥夺条件**：线程获得的资源在未使用完前不能被强制剥夺
4. **循环等待条件**：形成资源等待环路

**避免策略**：
1. 破坏请求与保持：一次性申请所有资源
2. 破坏不可剥夺：获取不到资源时主动释放已持有资源
3. 破坏循环等待：按序申请资源
4. 超时机制：设置获取锁的超时时间

#### happens-before原则

JMM定义的操作间偏序关系，如果操作A happens-before 操作B，则A的执行结果对B可见。

**基本规则**：
1. 程序顺序规则：线程内按程序顺序执行
2. 监视器锁规则：unlock happens-before后续lock
3. volatile规则：volatile写 happens-before后续读
4. 线程启动规则：Thread.start() happens-before线程内操作
5. 线程终止规则：线程所有操作 happens-before线程终止检测
6. 中断规则：interrupt() happens-before检测中断
7. 传递性：A→B，B→C，则A→C

#### Java原子类家族

Java提供丰富的原子类，位于java.util.concurrent.atomic包：

**基本类型**：AtomicInteger、AtomicLong、AtomicBoolean
**数组类型**：AtomicIntegerArray、AtomicLongArray、AtomicReferenceArray
**引用类型**：AtomicReference、AtomicStampedReference、AtomicMarkableReference
**字段更新器**：AtomicIntegerFieldUpdater等

#### 阻塞队列实现原理

BlockingQueue继承Queue，提供阻塞的put和take方法。

**常见实现**：
- ArrayBlockingQueue：基于数组的有界阻塞队列
- LinkedBlockingQueue：基于链表的无界阻塞队列
- PriorityBlockingQueue：支持优先级的无界阻塞队列
- DelayQueue：延迟队列，元素到期才能被取出
- SynchronousQueue：同步队列，直接传递元素

#### 并发工具类详解

##### CountDownLatch
允许一个或多个线程等待其他线程完成操作。计数器初始化为N，每次countDown()减1，计数器为0时等待线程被唤醒。

**使用场景**：主线程等待多个子线程完成初始化。

##### CyclicBarrier
允许一组线程相互等待到达公共屏障点。计数器初始化为N，每次await()减1，计数器为0时所有等待线程被唤醒，可重复使用。

**使用场景**：多线程计算结果合并。

##### Semaphore
信号量，控制同时访问特定资源的线程数量。本质是计数器，acquire()获取许可，release()释放许可。

**使用场景**：限流、数据库连接池等资源池管理。

##### Exchanger
允许两个线程在交换点交换对象。两个线程都到达交换点时彼此交换数据。

**使用场景**：遗传算法中数据交换，生产者消费者模式。

### 链表反转算法实现

```java
import 持续交卷.算法.ListNode;

class Solution {

    /**
     * 思路是一个一个进行反转
     * 
     * 需要一个prev作为头结点，一开始是null，后面逐渐后移
     * 
     * 需要一个current代表当前节点，逐渐往后移动
     * 
     * 注意反转后链接会断开，所以需要一个temp保存next节点
     * 
     * 双指针，一前一后往后移动，直到后面那个指针为null
     * 
     * @param head
     * @return
     */
    public ListNode reverseList(ListNode head) {
        ListNode prev = null;

        ListNode current = head;

        while (current != null) {
            // 1. 临时保存当前节点的下一个节点。因为反转后链接断开了
            ListNode nextTemp = current.next;
            // 2. 反转指向，将当前节点指向前一个节点
            current.next = prev;
            // 3. 指针后移，prev移动到当前节点，curr移动到下一个
            prev = current;
            current = nextTemp;
        }

        return prev;
    }
}
```

**算法复杂度分析**：
- **时间复杂度**：O(n)，其中n为链表长度，需要遍历一次链表
- **空间复杂度**：O(1)，只使用了常数个指针变量
- **稳定性**：原地反转，不需要额外空间
