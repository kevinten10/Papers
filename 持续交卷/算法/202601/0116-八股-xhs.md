## 1. 字符串的最长无重复字符子串长度

### 题目描述
给定一个字符串，找出其中最长无重复字符的子串的长度。

### 解题思路
使用滑动窗口算法，维护一个窗口[left, right]，确保窗口内的字符都不重复。
- 使用HashSet记录窗口内的字符
- 当遇到重复字符时，移动左指针直到重复字符被移除
- 记录最大窗口长度

### 代码实现
```java
public int lengthOfLongestSubstring(String s) {
    Set<Character> set = new HashSet<>();
    int left = 0, maxLength = 0;

    for (int right = 0; right < s.length(); right++) {
        while (set.contains(s.charAt(right))) {
            set.remove(s.charAt(left));
            left++;
        }
        set.add(s.charAt(right));
        maxLength = Math.max(maxLength, right - left + 1);
    }

    return maxLength;
}
```

## 2. 字符串的全子集

### 题目描述
求给定字符串的全子集，例如"123"的全子集有：空，1，2，3，12，13，23，123

### 解题思路
- 可以使用位运算或递归回溯
- 字符串长度为n，则有2^n个子集
- 每个子集对应一个二进制数，位为1表示选择该字符

### 代码实现
```java
// 方法1：位运算
public List<String> getAllSubsets(String s) {
    List<String> result = new ArrayList<>();
    int n = s.length();
    int total = 1 << n; // 2^n

    for (int i = 0; i < total; i++) {
        StringBuilder sb = new StringBuilder();
        for (int j = 0; j < n; j++) {
            if ((i & (1 << j)) != 0) {
                sb.append(s.charAt(j));
            }
        }
        result.add(sb.toString());
    }

    return result;
}

// 方法2：递归回溯
public List<String> getAllSubsetsBacktrack(String s) {
    List<String> result = new ArrayList<>();
    backtrack(s, 0, new StringBuilder(), result);
    return result;
}

private void backtrack(String s, int index, StringBuilder current, List<String> result) {
    result.add(current.toString());

    for (int i = index; i < s.length(); i++) {
        current.append(s.charAt(i));
        backtrack(s, i + 1, current, result);
        current.deleteCharAt(current.length() - 1);
    }
}
```

## 3. 数组最大连续子序列和

### 题目描述
给定一个整数数组，找出其中连续子序列的最大和。

### 解题思路
- 使用动态规划：dp[i]表示以第i个元素结尾的最大连续子序列和
- dp[i] = max(dp[i-1] + nums[i], nums[i])
- 也可以使用Kadane算法，空间复杂度O(1)

### 代码实现
```java
// 动态规划
public int maxSubArray(int[] nums) {
    if (nums == null || nums.length == 0) return 0;

    int[] dp = new int[nums.length];
    dp[0] = nums[0];
    int maxSum = dp[0];

    for (int i = 1; i < nums.length; i++) {
        dp[i] = Math.max(dp[i-1] + nums[i], nums[i]);
        maxSum = Math.max(maxSum, dp[i]);
    }

    return maxSum;
}

// Kadane算法（空间优化）
public int maxSubArrayKadane(int[] nums) {
    if (nums == null || nums.length == 0) return 0;

    int maxSum = nums[0];
    int currentSum = nums[0];

    for (int i = 1; i < nums.length; i++) {
        currentSum = Math.max(currentSum + nums[i], nums[i]);
        maxSum = Math.max(maxSum, currentSum);
    }

    return maxSum;
}
```

## 4. LeetCode 494 目标和

### 题目描述
给定一个非负整数数组和一个目标数S，找出数组中数字之和等于S的所有组合的数量。每个数字只能使用一次，但可以选择使用或不使用。

### 解题思路
- 可以使用动态规划：dp[i][j]表示前i个数字组成和为j的组合数
- 也可以使用递归回溯，但效率较低
- 目标是将数组分为两组，正数组和为P，负数组和为N，则P + N = sum，P - N = target，解得P = (sum + target)/2

### 代码实现
```java
// 动态规划
public int findTargetSumWays(int[] nums, int target) {
    int sum = 0;
    for (int num : nums) sum += num;

    if ((sum + target) % 2 != 0) return 0;
    int p = (sum + target) / 2;
    if (p < 0) return 0;

    int[] dp = new int[p + 1];
    dp[0] = 1;

    for (int num : nums) {
        for (int j = p; j >= num; j--) {
            dp[j] += dp[j - num];
        }
    }

    return dp[p];
}
```

## 5. synchronized与ReentrantLock区别

### 主要区别
1. **来源**：
   - synchronized是Java关键字，由JVM实现
   - ReentrantLock是java.util.concurrent包下的类

2. **锁的获取方式**：
   - synchronized是非公平锁
   - ReentrantLock默认是非公平锁，可设置为公平锁

3. **等待可中断**：
   - synchronized不可中断
   - ReentrantLock可以通过lockInterruptibly()实现可中断等待

4. **超时机制**：
   - synchronized不支持超时
   - ReentrantLock可以通过tryLock(long timeout, TimeUnit unit)设置超时时间

5. **释放方式**：
   - synchronized自动释放锁
   - ReentrantLock需要手动释放锁（try-finally）

6. **条件变量**：
   - synchronized通过wait()/notify()实现条件变量
   - ReentrantLock通过Condition接口实现更灵活的条件变量

### 使用建议
- 对于简单场景，使用synchronized
- 对于需要高级功能的场景，使用ReentrantLock

## 6. G1和CMS垃圾回收器区别

### CMS (Concurrent Mark Sweep)
- **适用场景**：低延迟应用
- **算法**：标记-清除
- **并发阶段**：并发标记、并发清理
- **优点**：停顿时间短
- **缺点**：
  - CPU资源消耗大（并发阶段占用CPU）
  - 产生内存碎片
  - 无法处理浮动垃圾

### G1 (Garbage First)
- **适用场景**：大堆内存、低停顿
- **算法**：标记-整理（Region间）、标记-清除（Region内）
- **分代**：逻辑分代，物理分区（Region）
- **特点**：
  - 可预测的停顿时间
  - 更大的堆内存支持
  - 更好的内存整理

### 主要区别
1. **分代方式**：
   - CMS：传统分代（年轻代、老年代、永久代）
   - G1：逻辑分代，物理分区

2. **垃圾回收算法**：
   - CMS：标记-清除（老年代）
   - G1：标记-整理（跨Region）

3. **停顿预测**：
   - CMS：无法精确控制停顿时间
   - G1：可设置最大停顿时间目标

4. **内存碎片**：
   - CMS：产生碎片，需要Full GC整理
   - G1：通过整理减少碎片

## 7. SQL：找出三天连续登录的用户

### 表结构
```sql
user_login (user_id, login_date)
-- 假设每天最多登录一次
```

### 解题思路
需要找出连续三天都登录的用户，可以使用以下方法：
1. 自连接
2. 窗口函数
3. 日期计算

### SQL实现
```sql
-- 方法1：自连接
SELECT DISTINCT a.user_id
FROM user_login a
JOIN user_login b ON a.user_id = b.user_id AND b.login_date = DATE_SUB(a.login_date, INTERVAL 1 DAY)
JOIN user_login c ON a.user_id = c.user_id AND c.login_date = DATE_SUB(a.login_date, INTERVAL 2 DAY);

-- 方法2：窗口函数（MySQL 8.0+）
WITH login_streak AS (
    SELECT user_id, login_date,
           DATE_SUB(login_date, INTERVAL ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY login_date) DAY) AS group_date
    FROM user_login
)
SELECT user_id
FROM login_streak
GROUP BY user_id, group_date
HAVING COUNT(*) >= 3;
```

## 8. DDD领域驱动设计

### 核心概念
1. **领域（Domain）**：业务问题的核心
2. **子域（Subdomain）**：领域划分
3. **限界上下文（Bounded Context）**：领域边界的明确定义
4. **实体（Entity）**：有唯一标识的对象
5. **值对象（Value Object）**：无唯一标识的对象
6. **聚合（Aggregate）**：实体和值对象的集合
7. **聚合根（Aggregate Root）**：聚合的根实体

### 设计原则
1. **通用语言（Ubiquitous Language）**：业务人员和开发人员使用相同的术语
2. **领域层隔离**：领域逻辑不应依赖基础设施
3. **依赖倒置**：高层模块不依赖低层模块
4. **单一职责**：每个类只有一个改变的理由

### 优势
- 提高代码的可维护性和可扩展性
- 更好地反映业务需求
- 减少技术债务

## 9. MySQL隔离级别及并发问题、主键递增好处

### 隔离级别
1. **READ UNCOMMITTED**：允许读取未提交的数据
2. **READ COMMITTED**：只能读取已提交的数据
3. **REPEATABLE READ**（MySQL默认）：在同一事务中多次读取同一数据结果一致
4. **SERIALIZABLE**：最高隔离级别，完全串行化执行

### 并发问题
1. **脏读**：读取到其他事务未提交的数据
2. **不可重复读**：同一事务中多次读取同一数据，结果不一致
3. **幻读**：同一事务中多次查询，结果集不一致

### 隔离级别与并发问题对应关系
| 隔离级别 | 脏读 | 不可重复读 | 幻读 |
|---------|------|-----------|------|
| READ UNCOMMITTED | √ | √ | √ |
| READ COMMITTED | × | √ | √ |
| REPEATABLE READ | × | × | √ |
| SERIALIZABLE | × | × | × |

### 主键递增的好处
1. **减少页分裂**：新记录总是插入到最后，减少B+树的重组
2. **提高插入性能**：避免随机I/O
3. **更好的缓存局部性**：相邻数据更可能在同一页中
4. **简化索引维护**：减少索引调整开销

2. **关注列表查看**
3. **粉丝列表查看**
4. **互关状态查询**

### 数据库设计
```sql
-- 用户关注关系表
CREATE TABLE user_follow (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    follower_id BIGINT NOT NULL,  -- 关注者ID
    followee_id BIGINT NOT NULL,  -- 被关注者ID
    status TINYINT NOT NULL DEFAULT 1, -- 1:关注 0:取关
```

- **读操作**：先读缓存，缓存 miss 再读数据库

## 13. 关注列表更新设计

### 问题分析
当用户A关注用户B时，需要：
1. A的关注列表添加B
2. B的粉丝列表添加A

### 方案设计
1. **数据库方案**：
   - 维护关注关系表
   - 通过JOIN查询获取列表

2. **缓存方案**：
   - Redis SortedSet存储关注列表（按关注时间排序）
   - Redis SortedSet存储粉丝列表（按被关注时间排序）

3. **更新策略**：
   - 同步更新：关注操作时同时更新两个列表
   - 异步更新：通过消息队列异步更新

### 性能优化
- **分页查询**：使用Redis ZREVRANGE分页
- **计数优化**：使用Redis计数器维护总数
- **缓存预热**：活跃用户的列表预加载到缓存

```
直播服务 → 消息队列 → 推送服务集群
```
