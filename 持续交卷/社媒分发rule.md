# 社媒分发规则 — 多平台内容发布工作流

## 概述

本文档定义了将 `持续交卷` 项目中的深度文章分发到多个社交媒体平台的标准化工作流。

**与 `文章处理rule.md` 的关系**：
- `文章处理rule.md`：处理 B 级日常笔记 → 公众号日报（聚合模式）
- `社媒分发rule.md`（本文档）：处理 A 级深度文章 → 多平台分发

**适用场景**：独立主题的深度长文（通常 3000 字以上），需要覆盖多个社媒平台。

**统一入口**：使用 `文章处理prompt.md` 中的标准 Prompt 可自动完成分级和路由，无需手动判断走哪个规则。

---

## 第一步：内容分级

写完原始文章后，先判断分级：

| 等级 | 特征 | 分发策略 | 示例 |
|:-----|:-----|:---------|:-----|
| **A级** | 独立主题、有深度、有数据/案例支撑、3000字以上 | 全平台分发 + 定制配图 | `0310-AICoding.md` |
| **B级** | 日常学习汇总、碎片知识整理 | 仅微信公众号（走 `文章处理rule.md`） | `0108-资讯.md` |
| **C级** | 纯笔记/备忘/草稿 | 不发布，留作素材积累 | 零散 todo、临时记录 |

**判断标准**：
1. 是否有明确的独立主题？（不是多个碎片拼凑）
2. 是否包含原创观点、数据支撑或实践案例？
3. 对目标读者是否有独立阅读价值？

以上三项全满足 → A级，否则 → B/C级。

## 第二步：多平台改写

### 平台特性总览

| 平台 | 语言 | 字数 | 语气 | 核心差异 |
|:-----|:-----|:-----|:-----|:---------|
| 微信公众号 | 中文 | 2000-3000字 | 专业但亲切，叙事感强 | 独立成文，引导收藏转发 |
| 知乎 | 中文 | 1500-2500字 | 理性客观，数据驱动 | 回答体切入，逻辑链完整 |
| 小红书 | 中文 | 600-1000字 | 口语化，短句+emoji | 视觉优先，干货清单体 |
| X/Twitter | 英文 | 5-8条推文（每条<280字符） | 简洁有力，观点鲜明 | Thread 格式，每条独立可读 |

### 2.1 微信公众号（精华浓缩版）

**定位**：独立成文的精华版，保留核心框架和金句，引导收藏转发。

**改写原则**：
- 从原文提炼核心框架，删去详细代码和配置示例
- 保留 2-3 个最打动人的数据点
- 保留所有金句（加粗或引用块）
- 开头用场景代入（"你是不是也遇到过..."）
- 结尾引导读者看完整版或收藏
- 提供 3 个备选标题

**结构模板**：
```markdown
**标题（三选一）：**
- [痛点切入型]
- [方案承诺型]
- [经验复盘型]

**摘要：** [1-2句话概括核心价值]

---

[场景代入开头，1-2段]

### [问题分析，2-3个要点]

### [核心方案/策略，精简为要点]

### [最有价值的方法论，保留细节]

### [总结金句 + 引导完整版]
```

**字数控制**：2000-3000字。原文超过10000字时，精简到原文的 20%-30%。

### 2.2 知乎（回答体/专栏）

**定位**：以"回答问题"的方式切入，数据翔实，逻辑链完整。

**改写原则**：
- 开头先说结论（"先说结论：..."）
- 多用数据和引用（论文、基准测试、行业报告）
- 逻辑链要完整：现象 → 原因 → 方案 → 验证
- 引用知名人物/机构的观点增加可信度
- 可以适当展开技术细节（知乎读者技术水平较高）

**结构模板**：
```markdown
**适合回答的问题：**
- [问题1]
- [问题2]
- [问题3]

**标题（专栏用）：** [标题]

---

先说结论：**[核心观点]**

[数据支撑，3-5个数据点，带来源]

[原因分析]

**[方案/方法论]**

[步骤拆解，每步带简要说明]

**[最有价值的方法论展开]**

---

**总结：[升华观点]**

[引导完整版]
```

**字数控制**：1500-2500字。保留原文中所有数据引用和来源。

### 2.3 小红书（干货笔记体）

**定位**：视觉化、碎片化、高信息密度。封面吸睛，正文短句+emoji+编号。

**改写原则**：
- 每句话不超过 20 字（口语化短句）
- 大量使用 emoji 作为视觉锚点
- 用编号清单替代段落叙述
- 提炼为"N 个经验/技巧/方法"的清单格式
- 结尾加标签（hashtags）
- 金句适合做图片文案

**结构模板**：
```markdown
**封面文案（图片大字）：**
[主标题]
[副标题/数字]
[附加价值点]

**标题：** [吸睛标题｜附xx模板/清单]

**正文：**

[场景共鸣，2-3行短句]

[核心认知，1句金句]

[经验一] [emoji]
[2-3行短句]

[经验二] [emoji]
[2-3行短句]

...

[金句收藏]

#标签1 #标签2 #标签3 ...（8-15个标签）
```

**字数控制**：600-1000字。原文的核心观点精简为 5-7 个要点。

**标签策略**：
- 核心标签（3-5个）：与文章主题直接相关
- 扩展标签（3-5个）：覆盖目标受众常搜的词
- 热门标签（2-3个）：当前平台热门话题

### 2.4 X/Twitter（英文 Thread）

**定位**：英文为主，每条推文独立可读但串起来成体系。

**改写原则**：
- 每条推文 < 280 字符（英文）
- 第 1 条：场景+悬念+预告（"Here are N lessons 👇"）
- 中间条：每条一个独立观点，带数据或类比
- 最后一条：总结 meta-lesson + 引导完整版链接
- 适度使用 emoji（不如小红书密集）
- 用数字编号（1/7, 2/7...）标记顺序

**结构模板**：
```markdown
**1/N**
[场景描述，制造共鸣]
[预告：Here are N lessons 👇]

**2/N**
Lesson 1: [观点]
[数据或案例支撑]
[一句话行动建议]

...

**N/N**
The meta-lesson:
[升华观点]
[核心金句]

Full article with templates: [link]
```

**推文数量**：5-8 条。少于 5 条信息量不够，超过 8 条读者流失率高。

## 第三步：配图生成

### 配图分类

| 类型 | 用途 | 数量 | 复用性 |
|:-----|:-----|:-----|:-------|
| **原文配图** | 文章正文中的流程图、架构图、对比图 | 5-8张 | 可跨平台复用 |
| **金句卡** | 核心观点的视觉化呈现 | 3-5张 | 跨平台通用 |
| **平台封面** | 各平台封面/头图 | 每平台1张 | 平台专属 |
| **平台专属图** | 适配平台视觉风格的特殊配图 | 每平台1-2张 | 平台专属 |

### 各平台配图规格

| 平台 | 封面尺寸 | 风格 | 配图数量 |
|:-----|:---------|:-----|:---------|
| 微信公众号 | 900x383（2.35:1） | 深色专业风，标题醒目 | 封面1 + 正文2-3 + 金句1-2 |
| 知乎 | 16:9 横版 | 暗色代码风，数据可视化 | 头图1 + 数据图1-2 + 金句1 |
| 小红书 | 3:4 竖版（1080x1440） | 粉/橙/黄暖色调，可爱活泼 | 封面1 + 轮播2-3 + 金句1 |
| X/Twitter | 16:9 横版（1200x675） | 暗色科技风，英文 | 首推图1 + 流程图1-2 + 金句1 |

### 金句卡设计规范

金句卡跨平台复用，设计时遵循：
- 尺寸：1080x1080（正方形，各平台通用）
- 背景：渐变色或纹理，避免纯白
- 文字：中文金句居中，字号大，加引号
- 底部：署名或文章标题（小字）
- 风格统一：同一篇文章的金句卡保持一致的视觉风格

### 生成工具

优先使用 `mcp__mcp-image__generate_image`（Gemini），prompt 需包含：
- 图片内容描述
- 尺寸要求
- 风格关键词（如 "dark tech style", "warm pastel"）
- 文字内容（如果图片需要包含文字）

**注意**：MCP 图片生成可能断连，建议：
- 批量生成时，每次生成 2-3 张后检查结果
- 失败时重试，不要跳过
- 记录已完成和未完成的图片清单

## 第四步：文件输出

### 目录结构

A 级文章的社媒版和配图与原文放在同一目录：

```
持续交卷/[模块]/[年月]/
├── [日期]-[主题].md              # 原文
├── [日期]-[主题]-社媒版.md        # 多平台改写合集
├── images/                        # 配图目录
│   ├── wechat-cover.png
│   ├── zhihu-header.png
│   ├── xiaohongshu-cover.png
│   ├── x-thread-header.png
│   ├── quote-[关键词].png         # 金句卡
│   └── [描述性名称].png           # 正文配图
└── SESSION-GUIDE.md               # （可选）会话记录，供后续会话参考
```

### 命名规范

- **社媒版文件**：`[原文件名]-社媒版.md`
- **平台封面**：`[平台]-cover.png`（wechat/zhihu/xiaohongshu/x）
- **平台专属图**：`[平台]-[描述].png`
- **金句卡**：`quote-[关键词].png`
- **正文配图**：`[描述性英文名].png`

### 社媒版文件结构

所有平台的改写内容放在一个文件中，按以下结构组织：

```markdown
# [文章标题] — 多平台发布版

---

## 一、微信公众号（精华浓缩版）

> 定位：[一句话定位]。约 XXXX 字。

[完整的公众号版内容]

---

## 二、知乎（回答体/专栏）

> 定位：[一句话定位]。约 XXXX 字。

[完整的知乎版内容]

---

## 三、小红书（干货笔记体）

> 定位：[一句话定位]。

[完整的小红书版内容]

---

## 四、X / Twitter（推文串 Thread）

> 定位：[一句话定位]。N 条推文。

[完整的 Thread 内容]

---

## 五、各平台专属配图清单

[配图对照表，标注每张图的文件名、所属平台、用途]
```

## 第五步：敏感信息检查

发布前必须检查：

- [ ] 不包含真实密码、token、API key
- [ ] 不包含真实的数据库连接串（示例用 `xxx` 或 `example.com` 占位）
- [ ] 不包含公司内部信息、客户数据
- [ ] 不包含他人隐私信息（手机号、邮箱等）
- [ ] 代码示例中的变量名不涉及真实业务

**示例占位符规范**：
- 数据库：`postgresql://test-db:5432/example`
- Token：`token=xxx`
- API Key：`sk-xxxxxxxxxxxx`
- 用户ID：`user_id=10086`

## 第六步：发布

### 发布 Checklist

```
□ 1. 内容分级确认（A级）
□ 2. 原文定稿（无遗留 TODO）
□ 3. 多平台改写完成（社媒版.md）
□ 4. 配图全部生成（检查 images/ 目录完整性）
□ 5. 敏感信息检查通过
□ 6. git commit + push

--- 以下为逐平台发布 ---

□ 7. 微信公众号
     - wenyan-mcp 上传草稿（或手动复制）
     - 上传封面图（wechat-cover.png）
     - 正文插入配图
     - 预览检查 → 发布

□ 8. 知乎
     - 找到合适的问题（或发专栏）
     - 复制社媒版第二节
     - 上传头图 + 正文配图
     - 发布

□ 9. 小红书
     - 复制社媒版第三节
     - 上传封面图（竖版）+ 轮播图（3-4张）
     - 添加标签
     - 发布

□ 10. X/Twitter
      - 逐条发推（1/N → N/N）
      - 每条配对应图片
      - 首推发完后回复串联
      - 发布
```

### 发布时间建议

| 平台 | 最佳发布时间 | 原因 |
|:-----|:-------------|:-----|
| 微信公众号 | 工作日 20:00-22:00 | 晚间阅读高峰 |
| 知乎 | 工作日 12:00-13:00 或 21:00-23:00 | 午休/睡前刷知乎 |
| 小红书 | 工作日 19:00-21:00 | 下班后浏览高峰 |
| X/Twitter | 工作日 09:00-11:00 PST | 北美科技圈活跃时段 |

## 完整工作流总结

```
原始文章完成
    │
    ▼
[1] 内容分级 ─── B/C级 → 走 文章处理rule.md 或不发布
    │
    A级
    ▼
[2] 多平台改写 → 生成 [主题]-社媒版.md
    │
    ▼
[3] 配图生成 → images/ 目录（封面 + 正文图 + 金句卡）
    │
    ▼
[4] 敏感信息检查
    │
    ▼
[5] git commit + push
    │
    ▼
[6] 逐平台发布（微信 → 知乎 → 小红书 → X）
```

**预估耗时**（基于 AICoding 文章经验）：
- 多平台改写：30-60 分钟（AI 辅助）
- 配图生成：30-60 分钟（含 MCP 重试）
- 检查 + 发布：30 分钟
- 总计：1.5-2.5 小时
