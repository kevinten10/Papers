# 我给 3 个 AI 取了三国的名字，结果它们真的开始"协作"了

最近做了一件挺中二的事：

我给三台电脑上的 AI Agent 分别取名叫「孔明」「卧龙」和「凤雏」。

不是闹着玩。
是因为我发现，当你认真设计 AI 的"人格"和分工之后，
它们的协作效率会比你想象得好很多。

## 为什么要这么搞

事情是这样的：
我手头有一台高配 Mac 和两台低配 PC。

以前就是随机开 Claude Code 干活，经常出现一个问题：
三台机器干的事重叠了，或者方向不一致。

后来我想到，现实中团队协作的关键不就是分工和角色吗？

于是我做了一个实验——

给每个 Agent 写了一份「灵魂文档」（SOUL.md），
不是简单的 system prompt，
而是详细描述了：

- 你是谁
- 你的核心职责
- 你的工作风格
- 你和其他人的关系
- 你的决策框架

## 三个角色怎么分的

**孔明**（高配 Mac）——决策者 + 主力开发
- 从想法池里筛选值得做的项目
- 承担核心代码和架构
- 协调另外两个 Agent 的任务
- 每日生成工作日志和反思报告

**卧龙**（低配 PC1）——深度思考者
- 负责技术架构设计和代码审查
- 不急着动手，先想清楚再说
- 提出"这个真的值得做吗"这种灵魂拷问
- 擅长跨界类比和反直觉观点

**凤雏**（低配 PC2）——行动派
- 快速把想法变成可运行的原型
- 先跑起来再优化，完成比完美更重要
- 遇到困难不说"不行"，只说"换个办法"
- 每天至少一个 commit

## 实际效果

跑了两天之后，数据是这样的：

- 评估了 29 个 AI 创业想法
- 筛出 8 个高价值方向
- 启动了 9 个项目仓库
- 完成了 5 个项目的 MVP
- 累计提交代码 37+ 次
- 知识库沉淀了 4 个核心技术文档

最让我意外的是，
孔明真的会在每天晚上 10 点自己写反思报告，
给自己打分，列出第二天的优先级。

不是我让它做的，
是它"灵魂"里写了这个节奏。

## 真正的价值不是角色扮演

有人可能觉得这就是给 AI 套了个三国皮。

但我觉得核心不在名字，而在结构：

1. **分工明确** → 避免重复劳动
2. **角色定位** → 每个 Agent 知道自己该做什么、不该做什么
3. **协作协议** → 通过 GitHub 实现异步协作
4. **质量把关** → 卧龙审查、孔明决策、凤雏执行，形成闭环

这其实就是把人类团队管理的经验，
迁移到了 AI 协作上。

## 给想玩多 Agent 的朋友的建议

1. **先想清楚分工再开动** —— 不要三个 Agent 干一样的事
2. **写好 SOUL.md 比写好 prompt 更重要** —— 人格决定行为模式
3. **用 GitHub 做协作枢纽** —— Issues、PR、Discussions 天然适合 AI 协作
4. **保留人类的最终决策权** —— AI 再厉害，方向还是你定

## 最后

这个项目叫 Romance of Three Claws（三爪演义）。

名字有点搞笑，但这套东西实际跑起来，
比我预期的要有用得多。

当你认真对待 AI 的"人格设计"，
它回馈给你的，远不只是一段代码。
