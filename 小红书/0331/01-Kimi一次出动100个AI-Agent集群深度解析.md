# Kimi 一次出动 100 个 AI，这和我用 3 个 Agent 开发有什么不同？

最近深度用了一段时间 Kimi，
发现一个很有意思的能力：

它可以一次性创建上百个 subagent，
同时去做同一件事的不同部分。

第一反应是震撼。
第二反应是：这和我之前搭的 3 人 AI 团队，到底有什么本质区别？

想了几天，终于想明白了。

## 先说 Kimi 的 Agent 集群到底在做什么

简单来说，就是 AI 版的「人海战术」。

一个复杂任务进来，Kimi 不是让一个 AI 从头想到尾，
而是把任务拆成 100 个小块，
每块派一个 agent 去执行，
最后把结果汇总。

用技术术语说，这是 **LLM 领域的 Map-Reduce**。

- Map：拆任务，100 个 agent 各干各的
- Reduce：收结果，合成一个完整答案

## 这种"百人出击"适合什么场景

不是所有任务都需要 100 个 agent。
但有几类场景，确实越多越好：

**1. 深度研究**

你问一个复杂问题，比如"2026 年 AI Agent 创业的机会在哪里"。
一个 agent 可能只搜到 3-5 个信息源。
100 个 agent 同时搜索，覆盖的信息面完全不同。

**2. 大规模文献综述**

读 100 篇论文，每个 agent 精读一篇，
最后合成一份综述。
人类做这件事要两周，agent 集群可能只要几分钟。

**3. 竞品分析**

想了解一个赛道有哪些玩家？
50 个 agent 同时调研 50 个竞品，
每个 agent 输出一份结构化分析。

**4. 多角度思辨**

让 100 个 agent 从不同立场论证同一个问题。
有的扮演支持者，有的扮演反对者，有的扮演用户，有的扮演投资人。
最后你看到的不是一个答案，是一个光谱。

**5. 代码审计**

大型项目几百个文件，一个 agent 根本看不完。
每个 agent 审查一个模块，最后汇总安全报告。

**6. 批量数据处理**

100 条用户反馈、100 份简历、100 个数据源——
每个 agent 处理一条，吞吐量线性增长。

## 但这和我之前做的多 Agent 完全不同

我之前用 OpenClaw + Claude Code 搭了一个 3 人 AI 开发团队：
孔明负责决策，卧龙负责深度思考，凤雏负责快速执行。

这两种模式的区别，我总结成一张表：

| | Kimi Agent 集群 | 我的 3 人 AI 团队 |
|---|---|---|
| **数量** | 几十到上百 | 3-10 个 |
| **关系** | 平级、同质 | 分工、互补 |
| **沟通** | 几乎不沟通，各干各的 | 通过 Git 协作、Review |
| **适合** | 信息搜索、并行处理 | 软件开发、创意协作 |
| **核心逻辑** | 用数量换覆盖率 | 用角色换决策质量 |
| **类比** | 100 个实习生查资料 | 3 个高级工程师造产品 |

一句话总结：

**Agent 集群是广度优先，角色团队是深度优先。**

## 我觉得真正有意思的地方

Kimi 的 agent 集群让我意识到一件事：

AI 的扩展方式和人完全不同。

人类增加人手，沟通成本会指数级上升（布鲁克斯法则）。
但 AI agent 增加到 100 个，如果任务本身可以并行，
沟通成本几乎为零。

这意味着：

- **搜索类任务**：agent 集群碾压单体 AI
- **创作类任务**：少量精细 agent 更合适
- **开发类任务**：角色分工 > 人海战术
- **分析类任务**：两种模式可以结合

未来可能最强的组合是：

**用 agent 集群做信息收集 → 用角色团队做决策和执行。**

先让 100 个 agent 把信息搜集齐，
再让 3 个专家 agent 来判断怎么用。

## 对普通人有什么启发

你不需要会写代码也能理解这个逻辑：

**1. 区分"搜索型任务"和"决策型任务"**

搜索型任务（查资料、对比方案、整理信息）→ 适合 agent 集群
决策型任务（选方向、定架构、做判断）→ 适合少量精细 agent

**2. AI 的价值不只是"更聪明"，还有"更多"**

一个很聪明的 AI 和 100 个普通的 AI 同时工作，
在很多场景下后者更有用。

**3. 未来的 AI 工具会越来越"编排化"**

不是一个对话框解决所有问题，
而是一个指挥官调度一群 agent 各司其职。

Kimi 走的是集群路线，Claude Code 走的是协作路线，
但方向是一样的：**单体 AI 的时代正在结束。**

## 最后

我之前以为多 Agent 就是"多开几个窗口"。
现在发现，Agent 的编排方式本身就是一种技术选择。

100 个 agent 一起查资料，是一种智慧。
3 个 agent 互相审查代码，也是一种智慧。

关键不在多少，
而在你理不理解自己的任务需要什么样的并行方式。

这可能是 2026 年用 AI 最重要的一个认知升级：

**不是"用不用 AI"的问题，
而是"怎么编排 AI"的问题。**
